## FSharp.AutoLisp：AutoLISP 语法检查器（fslex/fsyacc 版）

参照 `FSharp.RfcJson` 的三段式做法落地：

1. 文法文件：`FSharp.AutoLisp.Generator/autolisp.fslex`、`autolisp.fsyacc`。
2. 生成与验证：`AutoLispLexerTest.fs` / `AutoLispYaccTest.fs`，用 `FslexFilePrinter.forChar`、
   `FsyaccFilePrinter.from` 生成 `FSharp.AutoLisp/AutoLispLexer.fs`、`AutoLispYacc.fs`；
   `生成` 两个 Fact 平时 Skip，改了 .fslex/.fsyacc 后去掉 Skip 跑一次；其余 Fact 做表比对与冲突检查。
3. 串联：`AutoLispLexerTailer.fs`（DFA 出 token，补行号列号）→ `AutoLispCompiler.fs`（LALR 步进 + 错误位置）→
   `Validator.fs`（AutoLISP 特殊形式检查）→ `Library.fs` 的 `AutoLisp.check / checkFile`。

关键决定：

- 词法只按 AutoLISP 写：`;` 行注释、`;| |;` 块注释、字符串 `\" \\ \n \t \r \e \nnn`、符号字符集很宽（`1+` 是符号），
  数字只分整数/实数，没有 `#` 读取宏、没有点对。
- 语法只写 S-表达式结构（datum/list/quote），特殊形式不进文法，放在 AST 之上的 Validator。
- 行注释规则必须写成 `';' [^ '|' '\r' '\n' ] dot*`，否则最长匹配会吞掉 `;| ... |;` 后面的代码。
- token 的 lexeme 装箱成 `(text, SourceRange)`，语法动作里才能构造带范围的 AST。
- `FSharp.LexYacc.NextState` 与 `NextParseAction` 有同名分支，匹配时必须限定 `NextParseAction.*`。
- `Severity.Error` 会遮蔽 `Result.Error`，编译器内部改用私有 DU（ParseOk/ParseFailed）。

诊断编号：AL0001 多余右括号 / AL0002 左括号未闭合 / AL0003 词法失败 / AL0005 点对 /
AL0007 整数超 32 位 / AL0010 参数个数 / AL0011 该是符号 / AL0012 参数重复 / AL0013 参数表 /
AL0014 setq 或 / / AL0015 cond 子句 / AL0016 lambda / AL0017 缺函数体 / AL0018 foreach 无循环体 /
AL0020 &optional / AL0021 特殊形式当变量 / AL0022 调用头不是函数 / AL0023 全角字符 / AL0024 语法错误。

CLI：`FSharp.AutoLisp.Check`（程序名 autolisp-check），支持目录、`--json/--strict/--quiet/--no-builtin`。
测试：19 个运行时用例 + 6 个生成器用例（2 个 Skip）全绿；本仓库已用 git 初始化并提交。


## xUnitHost 接入后修的五处误报（实测驱动）

把本工具接进 `../xUnitHost` 当「送 acad 之前的语法闸门」后，拿仓里 12 份真实 .lsp 正文一跑，
立刻暴露工具自己的问题——**参数表/规则宁缺毋滥这句话要靠真实语料验证**：

- `tblobjname`：写成 (1,1)，实际 `(tblobjname 表名 符号)` = (2,2)。
- `textbox`：写成 (2,3)，实际 `(textbox elist [pt])` = (1,2)。
- `vl-catch-all-apply`：写成「至少 2 个」，acad 允许省掉参数表 → (1,2)。
- 点对 AL0005：`'(0 . "LINE")` 是 entmake 组码表的标准写法，一律报错错得离谱。
  改成带「这一段是数据」标记走树（进 quote/function 即数据），只在求值位置写 `.` 才报。
- `cond` 子句 `(T ...)`：被当成函数调用报「T 不是函数」。改成子句逐项当表达式走；
  顺带 defun/defun-q/defmacro/lambda 的参数表也不当调用检查（参数名可能就叫 car/list）。
- AL0023 全角字符：原来连注释里的中文标点都报（`checkFullWidth` 是纯文本扫描）。
  改成状态机，跳过 `;` 行注释、`;| |;` 块注释、`"..."` 字符串（含 `\` 转义）。

测试从 19 → 21 条（点对合法/求值位置报错、cond 用 T 不误报）。`../../FSharp.RfcJson` 那种
「先写文法再生成」的路线不变，只是语义规则要用真实脚本回归，不能只靠自己想的样例。

## docs 按实现修正（提交 `f5508e9`、`42a3a04`）

`docs/` 下的语法资料是 2021 年的，描述的是 ocamlyacc/Bison 与旧包 `FSharpCompiler.Yacc`，和现在的
`FSharp.LexYacc` 实现差得很远。这轮按代码逐条核对后重写/标注：

- `FslexFsyacc spec.md` **整篇重写**为当前实现的规范：`{...}` 头（可嵌套、原样抄进生成文件）、无 `%%`/无 `;`、
  段序固定（规则 → `%left` → `%type<T>`）、`let name = ...` 定义、模式里连接用 `&`、`%type<T>` 而非 `sym "Type"`。
- `fsyacc example.md` **整篇重写**：`%{ %}`/`%%`/`NUMBER "float"`/`ExprParseTable.parse` 全不成立，
  换成当前 API 的计算器例子，并在 F# Interactive 里实跑（17 / 5 / -4 / 14 / 1）。
- `编译原理用法.md`：注释改 `//` 与 `(* *)`（`/* */` 不是注释）、空白不含 Tab、"所有冲突都显式解决" 改成实际裁决规则。
- `token.md`：转义不是 JSON 那套（`\ \" \a \b \t \n \v \f \r \xNN \uNNNN`）；`parser.parse` 换 `nextAction`。
- `Yacc入门示例.md`、`Yacc使用优先级.md`、`Yacc用优先级和结合性解决冲突.md`：旧包教程，顶部加过时提示 + 指针。
- `Yacc Input File.md`、`yacc spec.md`：Bison 手册译文，顶部注明不是本项目格式。
- `Expression Simplification and Differentiation.md`：用原始 FsLex/FsYacc，注明技术栈。
- `AutoLISP 入门演练.md`：踩坑清单补「Tab 不是空白」「`%left`/`%type` 顺序」。

实测得到的、以后别再凭印象的结论：

- `%{ %}`／`%%`／`;`／`/* */`／`<name>` 引用／lex 模式里的 `"abc"` 字符串 —— **统统报错**（分别 `'%'`、`'%'`、`';'`、`'/'`、`'<'`、`NoSymbol "QUOTE"`）。
- `%type` 只能放最后：放规则前报 `NoSymbol "PERCENT_TYPE"`；`%left` 同理（`NoSymbol "%left"`）。
- 空白类 `[ ' ' '\r' '\n' ]` **不含 Tab**，文法文件里用 Tab 缩进直接 `Exception: '\t'`。
- 冲突：s/r 缺优先级 → 静默 shift；同优先级 `%nonassoc` → 该格动作被删（语法错）；r/r 或一格 >2 动作 → 建表时
  `failwith "[Reduce [...]; Reduce [...]]"`。`getConflictedProductions()` 报的是**裁决前**的冲突，
  所以靠 `%left` 的算式文法也会列出一堆，只有完全无冲突的文法才能断言 empty。
- 优先级级别 = `%left` 声明在文件里的行序（后者更高）；产生式优先级取 `%prec` → 头（头只有一条产生式时）→ 最右终结符。
- 归约函数模板：body 里的符号按 0 基下标绑 `let sN = unbox<T> ss.[N]`，头有 `%type` 才 `let result:T = ...; box result`，
  头没声明就丢掉动作结果返回 `null`。
